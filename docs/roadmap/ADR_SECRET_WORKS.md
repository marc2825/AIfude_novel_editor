# ADR：シークレット作品（パスワード付きの暗号化保存）

Status: Accepted（2026-11-20）。保護の強さ・ロックの単位・自動ロックは所有者が選択し、書き出し・同期・パスワード忘れの扱いは提案のとおり所有者が了承した。

## 目的

他人に見せたくない作品を、パスワードを入力しないと開けないようにする。所有者の選択は次の3つ。

- 保護の強さ：画面のロックだけでなく、保存データ自体を暗号化する。
- ロックの単位：作品ごとにシークレットをONにし、パスワードはアプリ全体で1つ。
- ロックのタイミング：再読み込み時と、10分間操作がないとき。手動の「今すぐロック」も置く。ロック中は一覧・タブのタイトルも「シークレット作品」と表示する。

パスワードを忘れると、誰も復元できない。この点は設定時に明示し、同意を得る。

## 鍵と暗号

- 追加の依存は使わず、ブラウザーのWebCryptoだけを使う。`127.0.0.1` は安全なコンテキストとして扱われる。
- パスワードはNFCに正規化し、PBKDF2-HMAC-SHA-256（600,000回、16バイトの乱数salt）で鍵暗号化鍵（KEK）を作る。
- 作品の暗号化には、乱数で作ったAES-GCM 256ビットのデータ鍵（DEK）を使う。保存するのはKEKで包んだDEKだけ。パスワードの変更はDEKを包み直すだけで、作品データは暗号化し直さない。
- 解錠中のDEKは取り出せない `CryptoKey` としてメモリだけに置く。ロック・再読み込みで破棄する。パスワードもDEKも保存・ログ出力しない。
- レコードごとに12バイトの乱数IVを使う。種類・作品ID・文書ID・保存versionなどの平文の付帯情報は、AES-GCMの追加認証データに含める。レコードの入れ替えや改ざんは復号の失敗として検出する。

## 保存形式

- IndexedDBに `workspace-vault` を追加する（DB v6）。中身は1件：KDFの設定、salt、包んだDEK、作成・更新日時。
- シークレット作品は、通常の作品と同じ構造の「シェル」として保存する。作品名・本文・章名・アウトライン・作品メモ・執筆設定・文体の指示を仮の値に置き換え、本物は任意項目 `secret`（`{ sealed: 1, kind: "workspace", meta, iv, data }`）に暗号化して入れる。保存履歴とごみ箱の記録もシェルを持つ。
- IDの割り当て・保存version・章の順序・日時はシェルに平文で残す。このため、保存versionの比較・作品の切替・削除・ごみ箱・保存履歴の処理は既存のコードのまま動く。暗号化と復号は、保存層の手前の `SecretWorkspaceRepository` が行う。
- IndexedDBのトランザクション中にWebCryptoを待つとトランザクションが自動で終わるため、暗号化はトランザクションの前、復号は読み込み後に行う。章の復元・コピー復元・ON/OFFの切替のようにIDや中身が変わる処理は、事前に復号・暗号化してから、トランザクションでは変更がないことだけを確かめる。
- 平文のシェルと暗号化したシェルが入れ替わらないよう、保存時に形式の一致を確認する。

当初はレコード全体を暗号化する案だったが、既存の処理がIDや保存versionを書き換える箇所（ごみ箱からの復元など）で暗号文と食い違うため、中身だけを暗号化するシェルの方式に変えた。

## 画面

- 設定で作品のシークレットをON・OFFする。初回はパスワードを2回入力し、忘れると復元できないことに同意する。
- ロック中の作品を開くと、本文の代わりにパスワード入力を表示する。AI・検索・組版・書き出しも使えない。
- ロック前に未保存の本文を暗号化して保存する。保存できない場合はロックせず、理由を表示する。

## 書き出し・同期

- 全作品バックアップでは、シークレット作品を暗号化したまま書き出し、包んだDEKも含める。復元にはパスワードが必要。
- 単体のJSON・テキスト・投稿用出力は解錠中だけ使え、暗号化されないファイルになることを確認してから書き出す。
- 端末同期の準備は、シークレット作品では使えない。

制限：保存履歴の名前・章の数・日時などは暗号化しない。同じ作品が残っている状態で、ごみ箱のシークレット作品をコピーとして復元することはできない（元の作品をごみ箱へ移してから復元する）。設定の「JSONバックアップを取り込む」で、開いているシークレット作品を置き換えることはできない。

## 採用しない案

- 画面ロックだけ：開発者ツールやバックアップから読めるため、所有者が選ばなかった。
- 作品ごとに別のパスワード：覚える数が増えるため、所有者が選ばなかった。
- パスワードの復旧：鍵をどこかに預けると暗号化の意味がなくなるため、提供しない。
