# Phase 3：執筆設定と部分採用

2026-10-27に承認した設計。作品保存形式をv5へ進め、PMスキーマとDBのstore構成は変えない。

## 執筆設定の保存と参照

`Project.authoringProfile` に人物の人称・呼称・口調・例・避ける表現、語彙表記、設定・関係・出来事・章要約の資料、文体観測、名前付きプリセットを保存する。各項目はID・revision・更新日時と、必要に応じて出典章・本文revisionを持つ。

既存の3欄メモは残す。出典章が削除されても履歴情報は保持するが、現在の根拠とは扱わない。コピー復元では出典IDも同じ対応表で再発行する。

旧v1〜v4を厳密に検証してから空のprofileを補う。読み込みだけでは元レコードを書き換えず、通常のCAS保存でv5にする。未知の将来形式は拒否する。旧版へ戻すときは更新前バックアップの別コピーを使う。

人物・資料・文体は生成ごとに選択し、初期OFF。送信内容を確認して、未信頼の `storyMemory` データとして構造化JSONを合成する。各2,000文字と入力全体の予算を守り、超過時は切り詰めず止める。プリセットの読み込みも利用者の操作とし、本文や資料から制御指示を自動で作らない。

## 保持条件と部分採用

必須指定した文字列は、適用する置換文字列で出現回数を検証する。変わっていれば採用を拒否する。保証するのは字面と回数だけ。人物・固有名詞・人称・数値の変化は警告とし、意味・視点・設定の維持は著者が確認する。

部分採用の差分は元snapshotと不変の候補からgrapheme単位で計算する。逆方向の計算で位置対応が変わる曖昧な差分や、過大な差分では部分採用できない。選んだhunk番号はセッション内に保持し、候補切替・再生成で解除する。

採用時に候補から最終の置換文字列を作り、通常と同じ同期検証・1トランザクション・1回のUndoで反映する。キーボードも同じ経路を使い、位置のmapping・再検索・自動rebaseはしない。
