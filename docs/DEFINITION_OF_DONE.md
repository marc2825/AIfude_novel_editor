# 完了条件

各Taskの完了時に、変更内容に当てはまる項目を確認する。

## 作業範囲

- 依頼されたTaskと完了条件に対応している。
- 無関係な整理・依存更新・整形や、将来用の空実装を含まない。
- 既存の未コミット変更を壊していない。

## コード

- TypeScript strictとlintが通る。
- 外部入力を境界で検証し、不要な `any` や型アサーションを追加していない。
- サーバー専用モジュールをクライアントへ渡していない。
- 本文・秘密情報をログへ出さず、利用者の文字列をHTMLとして解釈しない。

## エディタを変更した場合

- 選択の座標系が明確で、古いsnapshotを適用できない。
- 選択範囲外の文字を変えず、Reactから本文を上書きしない。
- Undo/RedoとIME入力を妨げない。

## 非同期処理を変更した場合

- リクエストIDを照合し、中止後の遅延応答を捨てる。
- 古いエラーで新しい状態を上書きしない。
- 再試行前に旧候補を無効にする。
- 採用の検証とdispatchの間にawaitを挟まない。

## 保存を変更した場合

- 書き込みを直列化し、保存バージョンを検証する。
- 失敗してもメモリ上の本文を残す。
- 読み込み失敗で既存データを上書きしない。
- バックアップ・取り込みの形式と参照整合性を検証する。

## 検査と文書

- 関連する単体・結合テストが通る。画面変更はコンポーネント、主要な操作の変更はE2E、ビルド境界の変更はbuildも確認する。
- 失敗したテストをskipして成功扱いにしない。未実行の検査は未実行と記載する。
- 公開する契約を変えたら仕様、設計判断を変えたら `docs/DECISIONS.md` を更新する。
- 制約・既知の問題を記録し、実機確認が必要な場合は結果か未実施を示す。

## 完了報告

対象Phase / Task、変更ファイル、完了条件との対応、実行コマンドと結果、残るリスクを報告する。既知の失敗が残れば完了としない。依頼された作業で止まり、次のTaskへ進まない。
