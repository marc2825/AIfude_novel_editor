# UX Specification

## Task 18.5：文脈で挿入

右端の「文脈で挿入 / Context Insert」を選び、書き足す位置へ範囲選択せずcaretを置く。右クリック→「文脈で挿入」、Shift+F10、Cmd・Ctrl+Kから「AI文脈挿入」を開く。初期空の「書きたい内容」にfocusし、未入力・空白のみ・500文字超では生成できない。目標1〜3,000文字（初期400）と候補数1〜3（初期1）も指定できる。

文中・先頭・末尾・空の章で使用可能。前後各最大1,000文字と作品設定、任意ONした作品メモを送信対象として確認できる。候補とDiff・実文字数を確認し、明示採用で元の本文の間へ挿入する。内容や目標を変えたら旧候補を破棄し、本文・caretが変わったら期限切れ。初期モードは引き続きRewrite。

## Task 18.4：Infill / Continue

右端に「中間補完」「続きを書く」を追加する。初期／reloadは書き直し。中間補完は途中の空白だけを選択するか空段落へcaretを置き、右クリック／Shift+F10／Cmd・Ctrl+Kで開く。前後に本文が必要。続きを書く場合は現在の章の最後へcaretを置く。無効な範囲は理由を案内し、本文変更・自動caret移動はしない。既存のprompt-only挿入から補完モードへ明示切替した場合も旧sessionを閉じる。

目標文字数1〜3,000（初期400）、編集の指示、候補数1〜3（初期1）を指定する。文字数は改行込みUnicodeコードポイントで、目標と実測を候補画面で併記する。生成は一回分の候補だけで、自動続きを生成しない。Diffと明示採用、1回Undoを使う。指示・目標・メモ参照の変更で旧候補を消し、本文／selection変更でstale化する。通常の本文編集と保存は生成中も使える。

## 画面構成

- 上部：作品名、保存状態、作品タブ、保存、ファイル、設定、AI接続。
- 中央：明朝体・広い行間の本文editor。原稿領域だけをスクロールできる。
- 右：メモリ、章、履歴の折りたたみパネル。設定・ファイルも上部の操作からこのパネルへ開く。
- 選択付近：右クリック→AI提案、またはCmd/Ctrl+Kで必要時だけ表示するAI popover。
- 常設チャット：なし。

モデルの主設定は「設定とバックアップ」内のAIモデル欄に置く。`自動（サーバー既定）`と現在providerでallowlistされたmodelを選択でき、表示名、canonical ID、providerの短い位置付け、Responses API / Structured Outputs対応、context・最大出力上限を示す。価格や文学的品質の順位は表示しない。

明示的に保存されたmodelが現在利用できない場合は、そのIDと利用不可状態を表示し、別modelまたは自動を選ぶまで生成を無効にする。自動は動的routingではない。

ChatGPTサブスク使用時は「設定とバックアップ」に接続状態、`Continue with ChatGPT`、接続解除を表示する。認証は別windowで行い、popupが開かない場合は認証リンクを表示する。初回接続時は利用枠が他のアプリと共有されることをdialogで案内する。接続は本文の保存・バックアップ・削除とは別に管理し、認証後も本文の外部送信には別途明示同意を必要とする。

初回案内は確認buttonまたはEscで通信完了前に閉じられる。確認状態のserver保存に失敗しても本文編集を妨げない。未保存の案内は次回のpage読込で再表示される。

サブスクのmodelはserver設定の具体的なIDを表示する。利用資格はアカウントのcatalogで確認し、未確認のcapabilityやcontext・最大出力token数は表示しない。接続開始、再認証、解除では開いているAI sessionを同期的に期限切れにする。認証失効・利用枠不足・接続失敗でも本文の編集と保存を維持し、別providerへ自動切替しない。利用枠不足の表示からChatGPTの利用枠管理へ案内する。

Task 18.1：補助パネルは初期状態で閉じる。開閉・切替でフォームをunmountせず、入力draft・editor instance・selectionを保持する。パネル内Esc／×で閉じた場合は起点のボタンへfocusを戻す。保存失敗・履歴記録失敗はパネルの開閉に関係なく確認できる。

## 状態遷移

Task 12.1：空のcaret位置でCmd/Ctrl + Kを押すと「AI文章挿入」を開き、プロンプトから候補を作る。標準1案で、候補確認・Diff・明示採用を経て挿入する。前後の本文・共通プロンプト・手動文体は送信しない。Task 13.1の作品メモリだけは明示ONで追加できる。本文やcaretを変更したら旧候補を期限切れにする。

複数接続をserverで設定した場合はコマンド内に比較用のAI選択を表示する。2〜3個を選んで対象すべてへの送信に同意し、「N個のAIへ同時送信」を実行する。提供元とmodelを付けて候補本文を横並び表示し、選んだ候補のDiffを確認して1件だけ採用する。選択対象を変更すると比較同意を解除する。一部の失敗は提供元ごとに表示し、成功候補は確認できる。AI比較のUIは必要なときだけ表示し、常設チャットにしない。

基本遷移：

Idle → Text Selected → AI Command Open → Generating → Candidate Preview。

Candidate Previewから：

- Accept → Idle
- Reject → Idle
- Retry → Generating
- 別候補選択 → Candidate Preview

補助状態：

- API失敗 → Error
- snapshot無効化 → Stale
- Esc → Idle

IdleはAIセッションが閉じている状態。本文に有効selectionが残っていれば、表示上はText Selectedとして扱う。

## 状態別仕様

| 状態 | 表示 | 許可する操作 |
|---|---|---|
| Idle | 本文 | 入力、選択、保存、設定 |
| Text Selected | 選択表示 | Cmd/Ctrl + K |
| AI Command Open | 指示、プリセット、候補数、送信対象、現在model | 生成、キャンセル |
| Generating | 進行表示、キャンセル | 本文編集、キャンセル |
| Candidate Preview | 候補、説明、注意、Diff | 採用、却下、再生成、候補切替 |
| Error | 安全なエラーメッセージ | 有効snapshotなら再試行、閉じる |
| Stale | 採用不可の理由 | 閉じる、新selectionから開き直す |

Generating中の指示、プリセット、候補数はread-onlyとする。

Preview中に指示や候補数を変更した場合、旧候補を破棄してAI Command Openへ戻る。自動送信はしない。

## Popover

非modalのdialogとして実装する。

本文編集を禁止するfocus trapを設けない。

selectionのhead付近をanchorとし、画面外へはみ出す場合はviewport内へ配置する。

高さのためanchorの上下に収まらない場合は利用可能領域内へ配置する。上部バー、右のツール列、開いている補助パネルを避け、サイズ変化・scroll・resizeでもviewport内に収める。原文は長い場合も省略せずスクロールで確認できる。

scrollやresizeで再配置するが、選択を作り直さない。

popover表示のためにPM selectionをcollapseさせない。

開く際は指示欄へfocusする。DOM focusが移ってもPM selectionが同一ならsessionは有効。

## キーボード

| キー | 条件 | 動作 |
|---|---|---|
| Cmd/Ctrl + K | editorにfocus、有効selection | AI入力欄を開く |
| Cmd/Ctrl + K | 同じ有効sessionが開いている | 指示欄へfocus。再送信しない |
| Cmd/Ctrl + Enter | 指示欄、生成可能 | 生成 |
| Cmd/Ctrl + Enter | popover内、Preview、採用可能 | 現在候補を採用 |
| Esc | AIセッション内、composition外 | cancelして閉じる |
| 左右矢印 | 候補tablistにfocus | 候補切替 |
| Home / End | 候補tablistにfocus | 最初・最後の候補 |
| Tab / Shift + Tab | 通常 | controls間を移動 |
| Enter / Space | buttonにfocus | buttonの操作 |

RetryとRejectはTabで到達可能なbuttonを必須とする。

Cmd/Ctrl + Enterをeditor全域のグローバルAcceptとして実装しない。

## IME

editorと指示欄のcompositionをそれぞれ追跡する。

`KeyboardEvent.isComposing`、editor viewのcomposing状態、compositionイベントの状態を確認する。

必要な互換対策としてkeyCode 229を扱う。

composition中のCmd/Ctrl + K、Enter、EscをAI操作に変換しない。

composition中に文字数制限のための自動truncateをしない。生成・設定保存の時点で検証する。

## 候補表示

初期選択は候補1。

各候補は以下を持つ。

- 本文
- 変更説明
- riskNotes
- Diff表示
- 「採用」「却下」「再生成」

candidate tabの切替は本文とUndo履歴を変更しない。

riskNotesがある場合は表示するが、完全な安全性判定として扱わない。

Diff計算が間に合わない場合、原文と候補の並列表現を表示し、Accept自体は妨げない。

## 選択解除

AIを開く前の選択解除はIdleへ戻る。

AIを開いた後の実質的なPM selection変更はStaleへ遷移する。

popoverへのfocus移動でDOM上の青い選択表示が消えるだけなら、selection解除とはみなさない。

必要ならDecorationで対象範囲を表示する。Decorationを本文marksとして保存しない。

## リクエスト中の文章変更

本文入力は許可する。

最初のdocument-changing transactionでsessionをstaleにする。

通信をabortし、遅延応答を破棄する。

「本文が変更されたため、この候補は採用できません。選択し直してください」と表示する。

変更箇所が選択外でも同じ扱いとする。

## リクエスト中のselection変更

caret移動を含め、実質的なselection変更でstaleにする。

元のselectionへ戻してもsessionを復活させない。

## API失敗とtimeout

本文を変更しない。

指示はsession内に保持する。

同じsnapshotが有効なら「再試行」を表示する。無効なら選択し直す案内を表示する。

料金が発生していないと断定しない。

## Esc

Generating中はabortを要求し、UIは直ちに閉じる。

Preview中は未採用候補を破棄する。

本文を変更しない。

popover内から閉じた場合はeditorへfocusを戻す。ただし古いselectionを再設定しない。

ユーザーがすでにeditor側で操作している場合、focusを奪わない。

## Undo / Redo

editorにfocusがある場合は本文のUndo/Redo。

指示textareaにfocusがある場合はtextareaの通常のUndo/Redoを妨げない。

AI適用直後のUndoはAI変更だけを戻す。

その後に手入力した場合、最初のUndoは手入力、次のUndoはAI適用を戻す。

Undo/Redoで候補UIやAPI呼び出しを再現しない。

## Retry

旧候補を先に利用不能にしてから新requestを開始する。

生成中に旧候補のAccept buttonを残さない。

stale状態ではRetry buttonを無効化する。

## 0文字・長すぎる選択

Task 12.1以降、0文字のTextSelectionは文章挿入を開く。空白・改行だけの非空選択の場合は編集入力欄を開かず理由を通知する。

2,000コードポイント超の場合、範囲を黙って切り詰めない。

「選択範囲を2,000文字以内に短くしてください」と表示する。文字数の基準はヘルプで説明する。

## Privacy UI

実AI初回使用時に以下を表示する。

- 送信先provider
- 選択範囲
- 前後文脈
- 共通プロンプト
- 手動文体設定
- 編集指示
- provider側の保持方針は別途適用されること

同意checkboxは初期off。

送信対象は折りたたみ表示で確認できる。

本文全文が送信されるように誤認させない一方、手動設定も外部送信対象であることを省略しない。

OpenAI内のmodel変更ではproviderとpolicy versionが同一なので既存同意を維持する。model表示は選択中の設定に追従し、候補Previewではserverが返した実使用modelを表示する。

## 保存状態

### 作品メモリ（Task 13.1）

本文の上に折りたたみ式の「作品メモリ（設定・背景・登場人物）」を置く。3つのnative textareaと文字数、明示的な「メモリを保存」を提供する。各2,000コードポイントまで。入力中に自動truncateせず保存時に検証する。保存失敗でも入力を保持し、同じ値で再試行できる。読み取り専用・import中は編集できない。

生成画面の「保存済み作品メモリを参照する」は初期OFF、新セッションでOFF。保存したメモが空なら無効。Task 14.1ではON時に設定・背景・登場人物のcheckboxを表示し、内容のある全項目を初期選択する。空の項目は無効。「送信するメモを確認」には選択したメモだけを文字列として表示する。OFFではメモを送らず、ONでは選択したAIへ追加送信する旨を示す。

未保存メモがあることを欄内へ表示する。再読み込み・離脱ではbrowser標準確認、取込・新規・作品切替・現在タブを閉じる・削除ではメモの破棄確認を行う。取消ならdraftと本文・AI状態を維持し、保存失敗でもdraftを残す。browserによって離脱確認の表示にはユーザー操作等の条件がある。

参照ON/OFFの変更で旧候補を破棄し、メモの保存変更で生成中・Previewを期限切れにする。入力予算超過は生成前に案内し、メモの短縮またはOFFを促す。メモ保存・参照変更では本文やUndo履歴を変更しない。AIはメモを自動更新しない。JSONバックアップへ含まれることを表示する。

### 共通の保存状態

Task 14.1で作品タブとファイル操作barを本文の上へ追加する。新規、開く、保存、JSONで保存、保存済み作品を開くをkeyboard操作できる。保存はCmd/Ctrl + Sでも実行し、IME composition中は横取りしない。開く操作は別の作品としてロードする。既存backup取込は現在作品の置換として区別する。

タブは左右矢印・Home / Endでfocusを移し、Enter / Spaceで切替する。閉じる操作ではデータを削除せず、保存済み一覧から再度開ける。最後のタブは閉じられない。切替中は「作品切替中」、失敗時は理由を表示し現在のeditorを維持する。Task 15.1では切替後もその章のUndo・caretを保持し、AI候補だけを破棄する。reload後は保存したタブの開閉を復元する。

表示は「未保存」「保存中」「保存済み」「保存失敗」の4種類。

保存失敗時も本文を編集可能に保つ。

別タブは「他のタブが編集中のため読み取り専用」と表示する。

削除、import、画面離脱では未保存状態を確認する。

## Accessibility

Task 12.1のAPI設定は「設定とバックアップ」で明示的にONにする。初期OFF・reloadでOFFに戻ること、APIがサブスクとは別料金であることを表示する。比較候補のAPI接続はOFF中に選択できない。設定変更時は進行中AIセッションを期限切れにする。Claudeサブスクは公式CLIへ事前ログインする方式であることを設定画面に示す。

候補tabとtabpanelを関連付ける。

popoverにはラベルを付け、aria-modalはfalse。

Generating、Error、Staleをlive regionで簡潔に通知する。

Diffは追加と削除の意味をテキストでも提供する。

候補全文をstatus announcementに含めない。


## 基本執筆機能（Task 15.1）

章とアウトラインは折りたたみ可能。現在章、並び順、追加・上下移動・削除を明示する。改名・アウトラインは明示保存し、未保存draftは離脱や作品切替で通知する。最後の章は削除不可、削除確認を要求する。Cmd/Ctrl+Sは本文・メモ・章draftを保存する。

保存履歴は初期閉じ、名前付きの手動保存と任意ONの自動記録を提供する。全章・メモ・設定の差分preview、取消、明示確認後の復元、履歴削除を提供する。復元前の状態も保存されること、直近50件の保持を説明する。一括backupは単体JSONと別の操作で、追加する作品数とコピー方式を復元前に確認する。

検索・置換はボタンまたは本文内のCmd/Ctrl+F / Hから開く。composition中は横取りしない。検索語・置換文・case・一致件数・対象を示し、1件／全件置換は確認後に実行する。変更後は旧検索を無効化し再検索を求める。文字数・目標は本文上部に表示し、改行除外の数え方を明記する。

タブ・caretの永続化が使えない場合は通知するが本文の編集保存を維持する。reloadでUndo stackが戻るとは表示せず、保存履歴からの復元を案内する。

## 未保存設定・ごみ箱・接続管理（Task 16.1）

作品設定の未保存draftも画面内表示と離脱・作品切替・単体import・削除の確認対象。Cmd/Ctrl+Sと通常保存で保存でき、取消や失敗でdraftを失わない。破棄確認の取消は生成中・Previewの状態を変更しない。

「ごみ箱・削除の復元」は初期閉じ。作品／章、名称、削除日時、復元、完全削除を表示する。章は元の作品を開いた場合だけ復元できる。復元と完全削除の各操作で確認し、現在の本文は上書きしない。最大200件、完全削除まで保持することを表示する。履歴がなくても復元できる。

「AI接続の設定・診断」も初期閉じ。主接続・比較候補・モデル・ローカルURLを設定できる。アプリ全体へ適用され作品backupに含まれないこと、認証情報はserver管理であることを表示する。未保存接続設定は離脱通知と通常保存へ統合する。保存後はAPI許可をOFFにし、進行中AI候補を期限切れにする。診断は保存済み設定にだけ実行でき、本文・メモ・プロンプトを送らず、生成・品質・残量を保証しない旨を表示する。取消後の遅延結果は表示しない。

## Task 18.1：右クリックと日本語の推敲比較

- 有効な選択で右クリックすると「AI提案」のmenuを表示する。Shift+F10 / ContextMenuキーでも開ける。menuitemの選択で既存controllerを呼び出し、生成は明示操作まで行わない。
- メニュー中の本文／selection変更でメニューを破棄し、古い選択を復元しない。IME composition中、読み取り専用、空選択ではnative context menuを横取りしない。
- 日本語推敲の補助指示として語尾重複・文のリズム・視点のぶれを追加する。既存の保守的なcustom intentを使い、意味保存の保証や新しいLLM呼び出しを追加しない。
- Previewでは複数候補をカードで比較する。提供元・model・文字数差・候補本文と、選択中の本文／Diff・説明・注意を確認できる。候補切替は既存tablistの左右・Home/Endでも操作できる。
- Preview中の生成条件は「指示・送信設定を変更」の中へ折りたたみ、比較と採用を先に見せる。指示変更で従来どおり旧候補を破棄する。採用・却下・再生成は独立した明示操作とする。

## Task 18.2：右端のAIツール選択

右のツール列にnative radioの5種類（書き直し・文体変換・膨らませる・短くする・自由指示）を表示する。初期値は書き直し。マウス・Tab・矢印キーで選び、選択状態は色・枠・radioのcheckedで示す。起動中の作品切替では保持し、reloadで書き直しに戻す。

ツール選択だけでは本文・PM selection・Undo・保存内容を変更しない。モード変更で開いている選択範囲のAI sessionを閉じてabortし、旧request IDの結果を破棄する。次の右クリック／Cmd・Ctrl+Kから新モードで開く。既存のプロンプト挿入セッションには介入しない。生成には従来どおり明示操作と同意が必要。

popover上部に選択モードの日本語名・英語名を表示する。Transformでは雰囲気・強さから編集指示を構成し、その指示を直接調整することもできる。Expand・Condenseには初期指示を入れ、Customは空の自由指示から始める。TransformとCustomは指示が空なら生成不可。追加指示を入力してもそのモードのpresetを保持する。Rewriteでは従来のプリセットと日本語補助指示を使用する。

IME compositionの判定は追加した雰囲気入力欄も含め、確定やEscをAI操作へ転用しない。空selectionの既存プロンプト挿入は5ツールと独立する。新しい事実・出来事・視点を創作するモードは追加しない。

## Task 18.3：辞書モード

右端のradioへ「辞書 / Dictionary」を追加する。選択範囲の右クリック項目と本文の操作ヒントも「辞書で調べる」に変わる。1〜100文字の語句から非modal「語句を調べる」を開く。空selectionでは文章挿入を開始せず、語句の選択を案内する。

「LLMで調べる」は現在の主AIを使い、保存済みの外部送信同意とAPI opt-inを要求する。送信対象は語句と固定指示だけで、説明は本文外に表示する。採用・Diff・挿入を提供しない。「Googleで意味を検索（別タブ）」は選択語句と「意味」を明示clickで外部送信する通常リンク。LLMが無効でも検索可能とし、どちらへも自動送信・自動fallbackしない。

生成中の本文編集と保存は維持する。照会中止は結果を破棄して照会ボタンへfocusを戻す。閉じる／Escは現在のeditorへfocusを戻し、旧選択を復元しない。本文・selection・参照設定の変更はstaleにし、照会結果と検索リンクを無効化する。モード／作品切替・unmountでもabortし、遅延結果を破棄する。LLM説明は出典付き辞書や実検索結果とは区別する。

## モバイルPhase 1：本文中心のタップ導線

900px以下では「作品操作」に新規・open・JSON保存・保存済み作品選択をまとめ、「保存」と保存状態、作品タブを常時表示する。下部のAIツール選択、メモリ・章・履歴から同じフォームを開く。パネル開閉・回転で入力draftを捨てず、未保存のメモ・設定はパネル外にも通知する。引き出しは閉じるbuttonへfocusし、×/Escで起点へ戻る。

本文を選択して「AI提案」をタップする。辞書・中間補完・続き・文脈挿入は選んだツール名のbuttonになる。先にツールを選び、必要な範囲/caretを指定する。native長押し選択をアプリのcontext menuで置き換えない。明示buttonのpointerdownではcomposition外でfocus移動だけを防ぎ、click時の現在のPM selectionをcaptureする。selectionが変われば従来どおりstale。旧selectionを復元しない。

小幅の候補はtabで1件ずつ切替し、原文、提供元・model、候補、Diff、採用/却下/再生成を確認する。sheetは非modalであり、生成中も本文を編集できる。VisualViewportとsafe areaに追従し、入力欄/内容を独立スクロールする。タップUndo/Redoは既存PM履歴を使い、composition中は実行しない。PCの右クリック、ショートカット、radioとカード比較も維持。

背景化/ページ非表示時は現在の保存queueへflushを要求するが、OS終了による完了は保証しない。「保存済み」は書込完了時だけ。設定等のdraftは通常保存で確定する。実機IME/選択/スクリーンリーダーの状況は Phase 1 report（開発履歴・配布対象外） を参照。

スマホのAI画面上部の「本文へ」で指示・候補を保持して本文に戻り、「AI画面に戻る」で再表示できます。生成中も利用でき、本文や選択を変えた場合は保持中の候補を期限切れにします。閉じる操作はそのAIセッションを破棄します。
