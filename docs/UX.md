# 画面と操作の仕様

利用者向けの手順は [操作ガイド](USAGE.md)、座標・更新処理の規則は [設計](ARCHITECTURE.md) を参照する。この文書は表示、操作、フォーカスの振る舞いを定める。

## 画面構成

本文を中央に置く。上部は1行のバーで、製品名、作品の切替メニュー、保存状態、AIの実行環境、保存を置く。左端の列（「執筆の補助」）に補助パネルの入口を8つ（作品、章、メモ、診断、履歴、組版、AI接続、設定）まとめ、パネルは列のすぐ右に開く。列には短い語だけを表示し、読み上げ名はパネルの正式名（作品メモリ、設定とバックアップなど）とする。幅1100px以下では、パネルを本文に重ねて開き、上部のAI実行環境の表示を省く。本文の上には、章名（章のパネルを開く）、検索、元に戻す、やり直す、AI提案だけの細い行を置く。幅1200px以上では本文の右に余白欄を確保し、AIの入力・候補・差分をそこに出す。待機時の余白欄には操作の案内だけを置き、やり取りの履歴は残さない。補助パネルは初期状態で閉じ、開閉・切替でもフォームやエディタを再生成しない。入力途中の値と選択範囲を保持し、保存や履歴のエラーはパネルの外からも確認できるようにする。

操作UIの基準文字は16px、列の項目名・ツール名・候補タブは14px以上。AIツールは待機時には並べない。対象を選んでAI入力欄を開いたあと、入力欄の中のラジオボタンで選ぶ。文章を選択していれば「選択範囲を直す」の5つ（書き直し・文体変換・膨らませる・短くする・自由指示）と辞書、カーソルだけなら「カーソル位置に書く」の6つ（指示から書く・中間補完・続きを書く・文脈で挿入・描写を足す・展開を指定）を出し、空白だけの選択は中間補完で開く。同じ種類で最後に使ったツールを起動中は覚え、覚えたツールがその位置に合わなければ「指示から書く」で開く。ラジオボタンは1つの名前でまとめ、標準の矢印キー操作を維持し、選び直してもフォーカスを選択肢に残す。ツールを選ぶだけでは送信も本文の変更もしない。選択を色・枠・太字、フォーカスを輪郭線で示す。アイコンは読み上げやフォーカスの対象にしない。

色は役割で使い分ける。緑は書き手の操作（保存、フォーカス、主ボタン）、金はAIに関わるもの（AI提案ボタン、対象範囲の印、AI入力欄、追加される文字）、朱は削除と採用できない状態を表す。色だけに頼らず、下線・取り消し線・文字のラベルを併用する。色・文字サイズ・角丸・影・重なり順は `src/app/globals.css` のトークンで定義し、OSの設定に合わせて明暗を切り替える。開閉と状態の変化には140ミリ秒以内の動きだけを付け、動きを減らす設定では止める。

補助パネルの見出しは左の線付きの太字、補足説明は小さめの淡い文字、状態とエラーは本文色で示し、区切り線でセクションを分ける。初期表示の説明は1行までにし、詳しい説明は見出しや項目の横の「?」（HelpTip）に置く。HelpTipはマウスのホバー・キーボードのフォーカス・タップで開き、Escと外側のタップで閉じる。説明文は `aria-describedby` で常に読み上げられ、見出しの名前には含めない。プライバシーと削除の注意は初期表示に残す。

Next.jsの開発用バッジは下部の診断ボタンを遮るため `devIndicators: false` とする。コンパイル・実行時エラーの表示は残る。[公式仕様](https://nextjs.org/docs/app/api-reference/config/next-config-js/devIndicators)。

## AI編集の流れ

本文を選択し、AI入力欄を開いて生成する。候補は本文の外で比較し、採用時にだけ本文へ反映する。常設チャットや、採用前に本文を置き換えるプレビューは設けない。

| 状態 | 表示 | 操作 |
|---|---|---|
| Idle | 本文 | 入力、選択、保存、設定 |
| Text Selected | 本文の選択範囲 | AI入力欄を開く |
| AI Command Open | ツール、指示、プリセット、候補数、送信内容、モデル | 生成、ツールの切替、キャンセル |
| Generating | 進行表示 | 本文編集、キャンセル。ツール・指示・プリセット・候補数は読み取り専用 |
| Candidate Preview | 候補、説明、注意、差分 | 採用、却下、再生成、候補切替 |
| Error | エラーと対処 | snapshotが有効なら再試行、閉じる |
| Stale | 採用できない理由 | 閉じる、新しい選択から開き直す |

採用・却下・EscでIdleへ戻り、再生成はGeneratingへ進む。指示や候補数を変えた場合は旧候補を捨てて入力に戻る。自動送信はしない。Idleでも本文に有効な選択が残っていれば、選択表示は残す。

## AI入力欄の配置

入力欄は非モーダルのdialogとし、本文編集を妨げるフォーカストラップを置かない。幅1200px以上では余白欄に置き、選択のheadと同じ高さに合わせて画面内に収める。この幅では入力欄が本文に重ならない。901〜1199pxでは本文の下に、高さが画面の50%までのトレイとして置く。対象がトレイに隠れる場合は、開いたときに1回だけ本文をスクロールして対象をトレイの上に出す。900px以下では下からのシートにする。作業画面の外（部品単体の表示）では、選択の近くに浮かべる。スクロール・リサイズ・内容の増減にも追従する。

入力欄を開いている間は、対象範囲を本文側にDecorationで示す。選択範囲には金の下地、カーソル位置には金の縦線を出す。本文のデータ・PM selection・Undo履歴・revisionは変えず、期限切れ・閉じる・採用で消す。本文が変わったときは、印を別の文字へ移さずに消す。

長い原文も省略せず、スクロールして確認できるようにする。再配置のためにPM selectionを作り直したり、縮めたりしない。開いた直後は指示欄にフォーカスする。DOMのフォーカスが移っても、PM selectionが同じなら候補は有効なままとする。

## キーボード

| キー | 条件 | 動作 |
|---|---|---|
| Cmd/Ctrl + K | 本文にフォーカス | 選択範囲やカーソルに応じたAI入力欄を開く |
| Cmd/Ctrl + K | 同じ有効セッションが開いている | 指示欄へ戻る。再送信しない |
| Cmd/Ctrl + Enter | 指示欄、生成可能 | 生成 |
| Cmd/Ctrl + Enter | AI入力欄内、候補を採用可能 | 現在の候補を採用 |
| Esc | AI画面内、IME変換中でない | キャンセルして閉じる |
| 左右矢印、Home / End | 候補タブにフォーカス | 候補を切り替える |
| Tab / Shift + Tab | 通常 | 操作部を移動 |
| Enter / Space | ボタンにフォーカス | 実行 |

再試行と却下もTabで到達できるボタンにする。本文全域にCmd/Ctrl + Enterの採用操作を割り当てない。

本文では本文のUndo/Redo、指示欄ではテキスト入力のUndo/Redoを使う。AI適用直後のUndoはAIの変更だけを戻す。その後に手入力した場合は、手入力、AI適用の順に戻す。Undo/Redoで候補画面やAPI通信を再現しない。

## IME

本文と指示欄の変換状態を別々に追跡する。`KeyboardEvent.isComposing`、エディタのcomposing状態、compositionイベントを確認し、互換対策としてkeyCode 229も扱う。

変換中のCmd/Ctrl + K、Enter、EscをAI操作へ転用しない。入力中の文字数制限による自動切り詰めも行わず、生成・設定保存の時点で検証する。

## 候補と期限切れ

初期選択は候補1。候補はタブで切り替え、原文との差分、候補の本文、変更説明、`riskNotes`、採用・却下・再生成を表示する。候補を受け取ったら表示を先頭へ戻し、差分を最初に見せる。原文の引用は差分と重なるため、候補の確認中は表示しない。検出した注意（`riskNotes`、字面の変化）は黄の枠、採用できない理由は赤の枠で示し、毎回出す注記と見分けられるようにする。注意事項は参考情報であり、安全性を判定した表示にはしない。差分計算が間に合わない場合は原文と候補を並べ、採用は可能なままとする。

本文の変更、カーソルを含むPM selectionの変更で、そのセッションをStaleにする。変更が選択範囲の外でも同じ扱いとし、通信を中止して遅延応答を捨てる。元の文章や選択へ戻してもセッションは復活しない。

本文変更時の案内は「本文が変更されたため、この候補は採用できません。選択し直してください」とする。DOM上の選択色が消えただけでは、選択解除とみなさない。必要な対象表示はDecorationで行い、本文のmarkとして保存しない。

再生成は旧候補を利用不能にしてから新しいリクエストを始める。生成中に旧候補の採用ボタンを残さず、期限切れの状態では再試行もできないようにする。

## 右クリックとツール

文章を選択して右クリックすると、「AI提案」と「辞書で調べる」のメニューを開く。Shift + F10 / ContextMenuキーにも対応する。メニューの選択では入力欄を開くだけで生成しない。本文や選択が変わればメニューを捨て、古い選択を復元しない。IME変換中・読み取り専用・空選択・空白だけの選択では、標準の右クリック操作を妨げない。

推敲ツールは書き直し・文体変換・膨らませる・短くする・自由指示。初期値は書き直しで、最後に使ったツールは作品切替では保持し、再読み込みで戻す。ツール選択だけでは本文・PM selection・Undo・保存内容を変えない。入力欄の中でツールを変えると、開いているセッションを閉じて旧応答を破棄し、同じ対象で新しいセッションを開く。対象に合わないツールを選んだ場合は理由を示し、開いているセッションと入力を保つ。生成中は選択肢を読み取り専用にする。

入力欄の題は操作の種類（AI編集コマンド、AI文章挿入など）とし、選んでいるツールはラジオボタンで示す。英語名は表示しない。文体変換は雰囲気・強さから指示を組み立て、送信前に調整できる。膨らませる・短くするには初期指示、自由指示には空欄を用意する。書き直し・文体変換・自由指示は空欄では生成できず、その理由を生成ボタンのそばに表示する。追加指示を入力しても、そのツールのプリセットを維持する。

書き直しには従来のプリセットに加え、語尾重複・文のリズム・視点のぶれを確認する補助指示を用意する。保守的なcustom intentを使い、追加のLLM呼び出しはしない。5つの推敲ツールでは新しい事実や出来事の創作を許可しない。

## 挿入と補完

| ツール | 対象 | 入力・送信内容 |
|---|---|---|
| AI文章挿入（指示から書く） | 空のTextSelection | プロンプト、標準1案。本文・共通プロンプト・手動文体は送らない |
| 文脈で挿入 | 文中・先頭・末尾・空の章のカーソル | 内容指示、前後各最大1,000文字、作品設定 |
| 中間補完 | 途中の空白または空段落。前後に本文が必要 | 指示、前後各最大1,000文字、作品設定 |
| 続きを書く | 現在章の末尾 | 指示、直前最大1,000文字、作品設定 |

保存済み作品メモリは参照をONにした場合だけ追加する。補完・文脈挿入では目標1〜3,000文字（初期400）、候補1〜3案（初期1）を指定できる。文脈挿入の内容指示は未入力・空白のみ・500文字超を拒否する。無効な場所では理由を示し、本文やカーソルを自動で動かさない。

文字数は改行込みのUnicodeコードポイントで、目標と実測を併記する。生成は一回分とし、候補・差分の確認と採用を経て反映する。指示・目標・参照の変更で旧候補を捨て、本文・カーソルの変更で期限切れにする。別のツールへ切り替えた場合も旧セッションを閉じる。

通常の選択編集は2,000コードポイントまで。超過時は切り詰めず「選択範囲を2,000文字以内に短くしてください」と案内する。空白だけの選択は通常編集では拒否し、中間補完では専用の条件で検証する。

## 辞書

「辞書」は1〜100文字の語句を対象とする非モーダル画面。文章を選んだときだけ、右クリックの「辞書で調べる」とAI入力欄のツールから開ける。空選択では語句の選択を案内し、文章挿入を始めない。

「LLMで調べる」は語句と固定指示だけを送る。外部送信同意と必要なAPI許可を確認し、結果は本文外に表示する。採用・差分・挿入は提供しない。「Googleで意味を検索（別タブ）」は明示クリックで語句と「意味」を送る。AIが無効でも検索は使える。

照会中止では結果を捨てて照会ボタンへ、閉じる・Escでは現在のエディタへフォーカスを戻す。古い選択は復元しない。本文・選択・参照設定の変更で結果と検索リンクを無効化し、ツールの切替・作品切替・破棄でも遅延応答を捨てる。説明は出典付き辞書や実検索結果と区別する。

## エラーとキャンセル

APIの失敗・時間切れでは本文を変えず、入力指示を残す。有効なsnapshotなら再試行、無効なら選び直す案内を出す。失敗した通信で料金が発生していないとは断定しない。

生成中のEscは中止を要求してすぐ閉じ、候補確認中は未採用候補を捨てる。AI画面から閉じた場合は本文へフォーカスを戻すが、古い選択を設定し直さない。すでに本文で操作を続けている場合はフォーカスを奪わない。

## 接続・モデル・送信同意

「設定とバックアップ」のAIモデル欄に、自動と対応モデルを表示する。自動はサーバーの既定モデルを使う。利用不能な保存済みIDはその状態を示し、別モデルか自動を選ぶまで生成を止める。

モデルの表示名・ID・提供元の説明・対応機能・入力と出力の上限を示す。価格や文学的品質の順位は表示しない。サブスクリプションのモデルはアカウントのカタログで確認し、未確認の性能・上限は表示しない。候補にはサーバーが返した実使用モデルを表示する。

ChatGPTの認証は別ウィンドウで行い、開けなければリンクを表示する。接続状態・解除、初回の利用枠共有の案内を用意する。案内は通信完了前でも閉じられ、確認状態の保存失敗で編集を妨げない。未保存なら次回表示する。接続開始・再認証・解除ではAIセッションを同期的に無効化する。

外部AIの初回送信前に、提供元、選択・前後文脈・作品設定・指示の送信範囲、提供元の保持方針が適用されることを説明する。同意は初期OFF。送信内容は折りたたみから確認できる。モデルだけが変わり、提供元とpolicy versionが同じなら同意を保持する。

有料APIは画面でも許可を必要とし、初期状態・再読み込み・接続保存後はOFF。比較先は2〜3個を選んですべてに同意し、同じ入力を送る。対象変更では比較同意を解除する。一部の失敗は提供元ごとに示し、成功候補は残す。利用枠不足や認証失効では本文編集と保存を続けられるようにし、別接続へ自動で切り替えない。

## 保存と作品管理

保存状態は「未保存」「保存中」「保存済み」「保存失敗」の4種類。書き込み完了前に保存済みと表示しない。失敗しても本文と入力途中の設定を保持する。別タブは読み取り専用の理由を表示する。

作品の切替メニューは、上部の作品名のボタンで開く。保存済みの作品の一覧と、新規作品・ファイルを開く・JSONで書き出す・作品を管理を並べ、開いている作品を `aria-current` で示す。Escと外側の操作で閉じる。切替中は状態を表示し、失敗した場合は現在のエディタを維持する。作品・章ごとのUndoとカーソルは起動中保持し、再読み込みでは最後に開いていた作品と対応するカーソルを復元する。Undo履歴の永続化は案内しない。

作品名・共通プロンプト・文体・メモ・章設定・接続設定の未保存状態を通知する。パネルを閉じても入力を保持し、通常保存とCmd/Ctrl + Sで保存する。IME変換中は保存キーを横取りしない。新規・切替・取込・削除などの破棄確認をキャンセルした場合は、入力とAIセッションを保持する。ブラウザーの離脱確認にはユーザー操作などの条件がある。

ファイルを開く操作は新しい作品として読み込み、設定内のバックアップ取込は現在作品の置換として区別する。開ける形式（.json / .txt、10MiBまで）はHelpTipで示す。切替メニューの「作品を管理」で開く「作品」パネル（ファイルとバックアップ）の保存済み作品一覧から、作品を開く・ごみ箱へ移す操作を確認付きで提供する。開いていない作品は保存履歴ごと1回のトランザクションでごみ箱へ移し、開いている作品は既存の削除と同じ経路で扱う。全作品のバックアップは単体JSONと別の操作にし、追加する作品数とコピー復元を確認する。

### シークレット作品

設定の「シークレット作品」で、作品ごとにON・OFFする。初回はパスワードを2回入力し、忘れると復元できないことへの同意を求める。解錠中は状態・ON/OFF・今すぐロック・パスワード変更を示し、ロック中は解錠フォームだけを示す。

ロック中の作品は、本文・AI・検索・組版の代わりにパスワード入力を表示する。作品の切替メニューと一覧は「シークレット作品」と表示し、パスワードを忘れた場合はごみ箱へ移す操作だけを提供する。上部には、解錠中は「ロック」、ロック中は「解錠」を置く。再読み込み時と10分間入力がないときに自動でロックし、保存できない・入力中のときはロックせずに1分後に再試行する。単体の書き出しは確認してから行う。

### メモ

設定・背景・登場人物は3つのテキスト欄で、各2,000コードポイントまで。保存時に検証し、失敗でも同じ入力で再試行できる。読み取り専用・取込中は編集できない。

AI参照は新しいセッションごとにOFF。ONにすると内容のある全項目を初期選択し、空欄は無効にする。「送信するメモを確認」には選択項目だけを文字列として表示する。上限超過では短縮かOFFを案内する。メモ保存は本文やUndoを変えず、AIからの自動更新はしない。JSONバックアップに含まれることも説明する。

### 章・履歴・ごみ箱・検索

- 章は追加・順序・削除の操作を示す。改名とアウトラインは明示保存し、最後の章は削除できない。
- 保存履歴は初期閉じ。名前付き保存と任意の自動記録、全章・メモ・設定の差分、確認後の復元・削除を提供する。復元前の状態も記録し、最大50件保持する。
- ごみ箱は初期閉じ。種類・名称・削除日時と、確認付きの復元・完全削除を示す。最大200件、完全削除まで保持する。章の復元は元の作品を開いて行い、現在本文は上書きしない。
- 検索は現在の章に限定し、検索語・置換文・大文字小文字の区別・件数・対象を示す。確認後に1件／全件を置換し、本文変更後は再検索を求める。文字数は改行を除くと明記する。

接続設定はアプリ全体に適用し、作品JSONに含めない。認証情報はサーバーで管理する。診断は保存済み設定に対してだけ実行し、本文を送らない。生成品質や残量の検査ではなく、取消後の結果も表示しない。

## 狭い画面とタップ

900px以下では補助パネルの入口の列を下部へ移し、8つを省略せずに1段に並べる。各入口は44px以上で、短い語を省略しない。幅360px以上では横にスクロールせずに収め、それより狭い画面では列を横にスクロールする。上部のバーは画面幅を超えない。作品の切替メニュー、保存状態、保存は上部に残す。同じフォームを使い、回転やパネル切替でも入力を失わない。

本文の選択後にAI提案をタップする。IME変換中でなければ、ボタンのpointerdownでフォーカス移動だけを防ぎ、クリック時のPM selectionを取得する。標準の長押し選択を独自メニューで置き換えない。

候補はタブで切り替え、提供元・差分・採用操作を画面内に収める。採用などの操作ボタンは1行に並べ、語の途中で折り返さない。VisualViewportとsafe areaに追従し、入力欄と内容をそれぞれスクロールできるようにする。タップのUndo/Redoも既存の履歴を使い、IME変換中は実行しない。

AI画面の「本文へ」で指示・候補を保持したまま執筆に戻り、「AI画面に戻る」で再表示できる。生成中も使える。背景化では保存キューを処理するが、OS終了前の完了は保証しない。

## アクセシビリティ

候補のtabとtabpanelを関連付け、AI入力欄にラベルと `aria-modal=false` を指定する。生成・エラー・期限切れを短いlive regionで伝える。候補全文を読み上げ通知に含めず、差分の追加・削除は色以外の情報でも区別する。

自動検査とキーボード確認を併用する。実機IME・選択ハンドル・スクリーンリーダーの確認状況は [公開準備](PUBLISHING.md) に記録する。
